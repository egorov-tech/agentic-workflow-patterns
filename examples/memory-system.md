# Memory system

Память агента — не лог переписки, а набор типизированных фактов с индексом.

## Типы

| Тип | Что хранит | Пример |
|---|---|---|
| `user` | роль, стек, уровень | «сильный backend, новичок во frontend — объяснять через аналогии» |
| `feedback` | коррекции и подтверждённые решения | «не мокать БД в интеграционных тестах — мок скрыл сломанную миграцию» |
| `project` | контекст, которого нет в коде | «переписываем auth из-за требований compliance, не ради рефакторинга» |
| `reference` | где искать во внешних системах | «баги пайплайна — в трекере, проект INGEST» |

## Формат записи

```markdown
---
name: no-db-mocks
description: integration tests hit a real DB, never mocks
type: feedback
---
Интеграционные тесты — только на реальной БД.
**Why:** мок прошёл, прод-миграция упала.
**How to apply:** любые тесты слоя данных.
```

`Why` важнее правила: по причине агент решает пограничные случаи сам.

## Индекс

`MEMORY.md` — одна строка на запись, всегда в контексте:

```
- [No DB mocks](no-db-mocks.md) — integration tests hit a real DB
```

## Что НЕ сохраняется

- то, что выводится из кода или `git log`
- рецепты фиксов (фикс уже в коде)
- временное состояние задачи

## Гигиена

- запись, противоречащая текущему коду, — обновить или удалить
- «память говорит, что функция X есть» ≠ «X есть сейчас»: проверить перед рекомендацией
- уроки проекта (`ошибка → правило`) формулируются с независимым advisor'ом до записи
